# moonlight-bridge-codegen

[![crates.io](https://img.shields.io/crates/v/moonlight-bridge-codegen.svg)](https://crates.io/crates/moonlight-bridge-codegen)
[![docs.rs](https://docs.rs/moonlight-bridge-codegen/badge.svg)](https://docs.rs/moonlight-bridge-codegen)
[![license](https://img.shields.io/crates/l/moonlight-bridge-codegen.svg)](https://github.com/MoonL1ghtProject/MoonLightBridge#license)

Schema compiler and compatibility checker for
[MoonLightBridge](https://github.com/MoonL1ghtProject/MoonLightBridge). It reads a standard Protobuf
descriptor set and produces matching Java and Rust RPC bindings with identical method IDs.

## Generated API

| Protobuf declaration | Java output | Rust output |
|---|---|---|
| `service ProfileService` | `ProfileServiceClient` | `ProfileService` trait and `register_profile_service` |
| unary `rpc Load(...)` | `load`, `loadBatch`, `withDeadline` | typed handler registration |
| top-level `NoticeEvent` | typed subscription helper | event ID and `publish_notice_event` |
| messages and enums | generated by `protoc` | generated by `prost-build` |

Protobuf remains the source of truth. The generator adds the transport layer around ordinary
generated messages; it does not introduce a second schema language. Generated method policy
constants avoid descriptor reflection on the request path.

## Requirements and installation

- Rust 1.88 or newer;
- `protoc` for Java message and descriptor generation;
- `prost-build` for Rust messages.

```bash
cargo install moonlight-bridge-codegen --version 0.4.0 --locked
```

## Contract example

```proto
syntax = "proto3";

package example.profile.v1;
option java_package = "dev.example.profile.v1";
option java_multiple_files = true;

import "moonlight/bridge/options/v1/options.proto";

service ProfileService {
  rpc LoadProfile(LoadProfileRequest) returns (ProfileResponse) {
    option (moonlight.bridge.options.v1.rpc_policy) = {
      timeout_ms: 2000
      retry: { max_attempts: 3 initial_backoff_ms: 25 max_backoff_ms: 250 multiplier_milli: 2000 }
      idempotency: IDEMPOTENCY_READ_ONLY
      max_request_bytes: 65536
      max_response_bytes: 1048576
      required_scopes: "profile.read"
      compression: COMPRESSION_MODE_PREFER
      trace_sample_per_million: 10000
    };
  }
}

message LoadProfileRequest { string player_id = 1; }
message ProfileResponse { string player_id = 1; int64 balance = 2; }

// The Event suffix enables typed server-push bindings.
message BalanceChangedEvent { string player_id = 1; int64 balance = 2; }
```

## Rust build script

```toml
[dependencies]
moonlight-bridge-server = "0.4.0"
prost = "0.14"

[build-dependencies]
moonlight-bridge-codegen = "0.4.0"
prost-build = "0.14"
```

Run models, descriptor generation, compatibility checking and service generation from `build.rs`:

```rust,no_run
fn main() -> Result<(), Box<dyn std::error::Error>> {
    moonlight_bridge_codegen::compile_rust_api(
        moonlight_bridge_codegen::RustBuildConfig {
            protos: vec!["../proto/profile.proto".into()],
            includes: vec!["../proto".into()],
            schema_lock: "../proto/schema.lock".into(),
            generated_services_name: "moonlight_bridge_services.rs".into(),
        },
    )?;
    Ok(())
}
```

`compile_rust_api` configures `prost-build`, writes a descriptor set, checks `schema.lock`,
generates services into Cargo's `OUT_DIR` and emits rebuild hints. See the complete working
[example API crate](https://github.com/MoonL1ghtProject/MoonLightBridge/tree/main/crates/moonlight-bridge-example-api)
for the model/service `include!` layout.

RPC policies are validated while the descriptor is compiled. Unsafe retries, streaming retries,
invalid scopes, unbounded message sizes, and invalid timeout, backoff, or sampling ranges fail the
build. The Rust output enforces request and response limits before handler dispatch and after
encoding. Java clients enforce the same limits and pass timeout and compression behavior to the
transport. Authorization, retry execution, and sampling are consumed by their respective runtime
components rather than implemented in generated handlers.

## Java CLI

Create one descriptor set and ordinary Java messages:

```bash
protoc \
  --proto_path=src/main/proto \
  --include_imports \
  --java_out=build/generated/proto-java \
  --descriptor_set_out=build/api.pb \
  src/main/proto/example/profile/v1/profile.proto
```

Generate typed MoonLightBridge clients:

```bash
moonlight-bridge-codegen build/api.pb build/generated/moonlight-bridge-java
```

Add both generated directories to the Java main source set. Recreate them during the build; do not
edit generated sources.

## Schema compatibility lock

Create or intentionally update the baseline:

```bash
moonlight-bridge-codegen lock build/api.pb schema.lock --update
```

Validate it in every build and CI run:

```bash
moonlight-bridge-codegen lock build/api.pb schema.lock --check
```

The checker rejects removed services/messages/methods, field identity or type changes, number reuse,
changed RPC signatures or policies, unsafe enum changes and generated ID collisions. Reservations recorded by
an existing lock must remain reserved in later schemas for both messages and enums. Adding a field
with a new number is compatible. To remove a field safely, reserve its old number and name:

```proto
message ProfileResponse {
  reserved 2;
  reserved "old_balance";
  string player_id = 1;
}
```

Review the lock diff before accepting it. Updating the lock suppresses the guard; it cannot make an
incompatible deployed schema compatible.

## Stable method IDs

RPC IDs are 32-bit FNV-1a hashes of `protobuf.package.Service/Method`. Both outputs embed the same
value. Renaming a package, service or method changes its wire ID and is a breaking contract change.
Event IDs use the same deterministic ID space.

## Gradle plugin

The Java plugin `ru.moonlightproject.bridge` wires generation into `compileJava` and compatibility
validation into `check`:

```kotlin
plugins {
    `java-library`
    id("ru.moonlightproject.bridge") version "0.4.0"
}

moonlightBridge {
    protoDirectory.set(layout.projectDirectory.dir("src/main/proto"))
    schemaLock.set(layout.projectDirectory.file("schema.lock"))
    codegenExecutable.set("moonlight-bridge-codegen")
}
```

Java artifacts are published to Maven Central. Ordinary Java applications use
`ru.moonlightproject:moonlight-bridge-java`; Paper/Folia plugins use
`ru.moonlightproject:moonlight-bridge-paper`. GitHub Packages remains an authenticated mirror.

## Current limitations

- unary and server-streaming response methods;
- top-level Protobuf request, response and event messages;
- events use the explicit `*Event` suffix;
- Java generation invokes a local `protoc`;
- client and bidirectional streaming schemas are rejected rather than partially generated.
