# Аудит безопасности MoonLightBridge 0.4.0

Дата проверки: 2026-10-04. Проверялись Rust-сервер, Java-клиент, генератор,
встроенная телеметрия, TLS-конфигурация, CI и выпуск артефактов.

## Исправленные риски

| Область | Риск | Исправление |
|---|---|---|
| Приём соединений | Не было общего ограничения числа соединений и времени чтения кадра | Добавлен `ServerLimits`: лимит соединений, общий бюджет декодированных запросов, timeout чтения кадра и timeout остановки writer-а |
| Идемпотентность | Ожидающие операции могли превысить ёмкость; panic оставлял ожидание навсегда или допускал опасный повтор | Ёмкость стала строгой; добавлены `Overloaded` и закреплённый `Indeterminate`; TTL считается от завершения операции |
| Java callbacks | Пользовательский event/stream callback мог остановить reader или убить его исключением | Event callbacks вынесены в ограниченный executor, stream callbacks сериализованы, исключения изолированы |
| Клиентские буферы | Пул мог удерживать около 512 MiB, а очередь больших запросов ограничивалась только числом элементов | Пул ограничен 16 MiB, запросы в очереди — 32 MiB; просроченные/отменённые запросы отбрасываются до записи |
| Handshake | Сервер мог объявить настройки выше локальных пределов клиента | `WELCOME` теперь проверяется против запрошенных максимальных значений и набора features |
| Отмена | Отмена типизированного или batch future не доходила до транспортного future | Генератор использует cancellation-aware mapping; batch отменяет дочерние запросы |
| TLS | `rustls 0.23.44` содержал исправленную позднее ошибку TLS 1.3; `rustls-pemfile` больше не поддерживается | Обновление до `rustls 0.23.45`, PEM читается через `rustls-pki-types`; проверяются mTLS и hostname rejection |
| Конфигурация TLS | Частично заданные переменные окружения могли незаметно включить plaintext | Пример backend-а завершает запуск с ошибкой при неполной или пустой TLS-конфигурации |
| Телеметрия | В удалённые события могли попасть текст, cause и stack trace исключения | Отправляются постоянные сообщения и стабильные коды; добавлены runtime opt-out и переопределение DSN |
| CI | Интеграционные транспорты и RustSec не блокировали изменения | Добавлены TCP/Unix/mTLS/reconnect проверки и отдельная проверка RustSec advisory |

## Производительность

- При отключённой телеметрии сервер больше не создаёт task-local список стадий и tracing span
  для каждой пользовательской функции.
- Кэш идемпотентности использует порядок завершения вместо полного прохода по таблице.
- Интеграционные проверки собирают backend один раз и повторно запускают готовый бинарник.
- Ограниченные callback-очереди не переносят работу пользователя на transport reader.
- Асинхронный reconnect-клиент загружает автоматическую телеметрию в supervisor-потоке,
  не задерживая вызывающий поток при старте.

## Сохраняющиеся ограничения

- Протокол возвращает владеющие `byte[]`/`Vec<u8>`; переход к zero-copy потребует другого
  контракта времени жизни данных.
- `IdempotencyCache` остаётся процессным. Для денежных и инвентарных операций ключ
  идемпотентности и optimistic concurrency должны проверяться в транзакции базы данных.
- Plaintext TCP допустим только в доверенной частной сети; для других сетей нужен mTLS.
- Бюджеты `ServerLimits` следует уменьшать или увеличивать по памяти и нагрузке конкретного
  backend-а. Значения по умолчанию не заменяют лимиты контейнера или systemd.

Проверка включала `cargo fmt`, Clippy с `-D warnings`, workspace tests и doctests,
Gradle `check`, а также TCP, Unix socket, mTLS, отрицательные TLS-сценарии и reconnect.
